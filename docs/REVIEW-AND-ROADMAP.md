# Website review and next additions

## Review findings addressed

- Project cards had no path to detailed work. Added six individual story pages and a filterable timeline with reversible date order.
- Sports history existed as long paragraphs. Structured the existing account into dated entries with room for reflections, images, and official results.
- Placeholder email, generic social URLs, and a missing CV PDF created dead ends. Removed them and used the verified public GitHub profile.
- Public copy included editing instructions and a blank education section. Removed those instructions, kept unsupported credentials unpublished, and improved the introductory copy.
- Added keyboard skip navigation, mobile Escape handling, larger menu touch target, active navigation on nested routes, readable text selection, a favicon, and a useful 404 page.
- Prepared a static export for Cloudflare so this content site needs no application server or database.

## Highest-value additions

1. **Three strong project case studies.** Add the original problem, your role, constraints, one useful diagram, real screenshots, and measurable outcomes where you have evidence. The tank controller, VBA automation, and Fit2U cover different strengths.
2. **A portrait and short biography.** Include your actual education, present role, and the opportunities you want to attract. Add public email, LinkedIn, and a real CV.
3. **Sports event stories.** Add race names, official result links, a few photos, training context, and what changed afterward. Use exact finish times only when verified. Add strength milestones if you want them public.
4. **Project progress within each story.** Use story sections for dated design, prototype, test, and release milestones. Show what changed between versions, including unsuccessful approaches.
5. **A current-focus page or short field notes.** Share what you are working on now and occasional notes from engineering or training. A small amount of maintained content is better than an empty blog.
6. **Optional editing interface.** When editing TypeScript becomes inconvenient, consider a Git-backed content editor or CMS with drafts, image uploads, and previews. Keep the existing data structure as the migration starting point.
7. **Discovery and feedback.** After a final domain is chosen, add canonical URLs, sitemap, social previews, and search indexing. Add privacy-conscious analytics only if the data will inform a decision.
